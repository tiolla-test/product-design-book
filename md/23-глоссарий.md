# Приложение Б. Глоссарий

| Термин | Что значит |
|---|---|
| A/B-тест | Сравнение двух вариантов на случайно разделённых группах пользователей |
| AARRR | Воронка роста: привлечение, активация, удержание, доход, рекомендации |
| Аффинити-карта | Группировка наблюдений исследования по смыслу |
| Атом | Простой компонент дизайн-системы: кнопка, поле, чип |
| Аудит интерфейса | Экспертная проверка по заранее названным ориентирам |
| Базовый уровень | Значение метрики до изменения |
| Бриф | Короткий документ с договорённостью о задаче |
| Вариант компонента | Другой вид при той же роли: размер, тип |
| Воронка | Последовательность шагов с долей людей, дошедших до каждого |
| Гаттер | Расстояние между колонками сетки |
| Гипотеза | Утверждение «если изменить X, метрика Y изменится, потому что Z», с методом проверки |
| Дизайн-долг | Отложенная работа по дизайну с записанной причиной и риском |
| Дизайн-система | Набор токенов, компонентов, паттернов и правил с документацией и связью с кодом |
| Допущение | Предположение, на котором стоит расчёт или решение, без подтверждения |
| Интерлиньяж | Межстрочный интервал |
| Каркас (wireframe) | Схема экрана без стиля |
| Карта пути (CJM) | Описание опыта человека по этапам: действия, мысли, каналы, боли |
| Композит | Компонент, собранный из атомов |
| Контрольная метрика | Метрика, которая не должна ухудшиться при изменении |
| Модель Кано | Классификация функций по влиянию на удовлетворённость |
| Модель эффекта | Расчёт ожидаемого эффекта решения с диапазоном и допущениями |
| MoSCoW | Приоритизация: Must, Should, Could, Won't |
| North Star | Главная метрика ценности продукта |
| Очередь | Список дел, ждущих действия конкретного человека |
| Паттерн | Известное решение повторяющейся задачи интерфейса |
| Персона | Описание типичного пользователя, основанное на данных |
| PRD | Документ с требованиями к продукту |
| Примитив (токен) | Токен, который называет значение: `blue/600` |
| Прогон сценариев | Проход всех путей и состояний прототипа руками или скриптом |
| Реестр | Полный список объектов, независимо от того, ждут ли они действия |
| Реестр сопоставления | Таблица связи фрагментов кода и компонентов дизайн-системы |
| RICE | Приоритизация по охвату, влиянию, уверенности и усилиям |
| Рабочий прототип | Прототип с логикой, данными и состояниями |
| Scope | Объём работы версии: что входит и что нет |
| Семантический токен | Токен, который называет роль: `color/text/muted` |
| Сценарий (user flow) | Путь человека к цели с развилками |
| Состояние | Вариант экрана или компонента в зависимости от данных и действий |
| Спецификация | Описание правил, значений и логики для разработки |
| Статус | Название состояния объекта, видимое человеку |
| Токен | Именованное значение дизайн-системы |
| HEART | Фреймворк метрик опыта: удовлетворённость, вовлечённость, освоение, удержание, успешность задач |
| JTBD | Jobs to be Done: описание задачи, ради которой человек использует продукт |
| WCAG | Международные правила доступности веб-содержимого |
| Юзабилити-тест | Наблюдение за тем, как человек выполняет задачи в интерфейсе |
